# AP LOI Builder

Draft Letters of Intent for commercial real estate. Pick a site, pick a template, fill in the blanks, pick optional language, edit inline, export as `.docx` or PDF.

## What's in here

- **The app** at `/app` — the pixel-perfect Figma build. Sidebar (Draft LOI / Build Template accordion), a middle panel that changes per step, a right-side `.docx` editor.
- **POCs** at `/poc/*` — small single-purpose pages that each prove one piece of the pipeline. They were how we settled on the stack and we keep them as evidence / regression tests.

## Routes

## The stack and why

| Need | Package | License | Why |
|---|---|---|---|
| Framework | React 18 + Vite 5 | MIT | What the team ships |
| Styling | Tailwind 3 | MIT | Fast, lets us hit Figma specs directly |
| Font | Poppins (Google Fonts) | OFL | What Figma uses |
| Icons | Hand-rolled SVG + lucide-react | MIT | Figma icons are custom — Lucide is a fallback |
| In-browser `.docx` editor | `@docx-editor.dev/react` | Apache 2.0 (Core) + commercial Pro | Jay approved; free Core covers v1 |
| Metric-compatible fonts for the editor | `@docx-editor.dev/fonts` | Apache 2.0 | So Calibri/Arial measurement doesn't drift inside the editor |
| Fill `[placeholders]` | `docxtemplater` + `pizzip` | MIT | Preserves Word XML byte-for-byte except the filled text runs |
| Fuzzy field match | `fuse.js` | Apache 2.0 | So `[LL Brokage]` still maps to `ll_brokerage` |
| Raster PDF export | `html2canvas-pro` + `jspdf` | MIT | one-click; bitmap text |
| Vector PDF export | native `window.print()` | — | pixel-perfect, no library |
| HTML → `.docx` round-trip (used in POC 4 only) | `@turbodocx/html-to-docx` | MIT | Proves the fidelity ceiling of a round-trip |
| `.docx` render for POCs | `docx-preview` | Apache 2.0 | Used in POC 1/4; the real app uses eigenpal |

### What we tried and dropped

- **SuperDoc** (`@harbour-enterprises/superdoc`) — AGPL-3.0. Great library, but the AGPL network-use clause makes it unusable for a hosted SaaS without their commercial license. We also hit a keypress crash on 1.46.3. Replaced with eigenpal.
- **Pure fill-and-preview** (docx-preview + contentEditable + html-to-docx round-trip) — the fidelity POC proved this loses images and complex tables on export. We ship it in POC 4 as the "cheap" path and documentation of the ceiling.

## Design system

- **Font**: Poppins. Loaded in `index.html` from Google Fonts.
- **Colours** (Tailwind config, `ap.*`):
  - `ap-text` `#404040` — primary text
  - `ap-text2` `#4e4d4d` — sidebar nav
  - `ap-dark` `#4b4b4b` — sidebar bars / dark accents
  - `ap-mid` `#b8b8b8` — sidebar body
  - `ap-light` `#dcdcdc` — middle panel bg + active nav row
  - `ap-cyan` `#00ffff` — `[placeholder]` highlight in the doc
- **Hard-coded extras** that didn't earn a token yet: `#777` (Update button + selected clause body), `#FBB040` (yellow accent for selected clause), `#F6F6F6` (clause card header bg).
- **Spacing**: Figma uses odd pixel values (22, 23, 42, 199, 427). We match them directly with Tailwind arbitrary values (`px-[22px]` etc.) rather than snapping to nearest-token. Pixel-perfect is the rule.

## Build Optional Language Library — this step in detail

The Figma for this step (node `108661:8114`) looks like a clause-browsing admin tool, not an inline edit form. The implementation:

- **Action bar** on top of the middle panel: `+ New Category`, `+ New Clause`, `Update Clause`, `Link`.
- **Scrollable list** underneath. Each category becomes a `<section>` with its heading and its clauses as cards.
- **Clause cards** have two visual states:
  - Not selected: light-gray `#F6F6F6` header, white body with `#404040` text.
  - Selected: yellow `#FBB040` header, dark `#777` body with white text, and a textarea for editing the body.
- **Drag reorder** inside a category uses native HTML5 drag/drop. The dragged card goes semi-transparent; drop on any other card to re-order.
- **+ New Category** prompts for a name and prepends it.
- **+ New Clause** appends an empty clause to the category of the currently selected clause (or the first category if nothing is selected). The new clause auto-selects so you can type its body immediately.
- **Update Clause** is active only when a clause is selected. Visually it mirrors the dark body of the selected card so the connection is obvious.
- **Link** is a stub for now — in the full product it anchors a clause to a position in the right-side template.

## Running it

```bash
npm install
npm run dev          # http://localhost:5173
npm run build        # production build
npm run make:sample  # regenerate public/templates/sample-loi.docx
```

Vite is configured with:
- Node polyfills (`vite-plugin-node-polyfills`) because `@turbodocx/html-to-docx` reaches for `Buffer` / `process` / `global`.
- `build.target: 'es2022'` because `@docx-editor.dev/*` ships top-level `await` in its PDF engine.
- An alias to the browser build of `@turbodocx/html-to-docx`.

## Backend swap

`src/lib/api/sites.js` and `src/lib/api/templates.js` are the seams. Today they return static data. When the NestJS backend lands, change the body of those two files — nothing else needs to move.
